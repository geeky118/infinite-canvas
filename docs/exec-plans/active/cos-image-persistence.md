# COS image persistence

## 目标

- 画布图片继续优先使用浏览器本地 IndexedDB 缓存，保证当前设备加载快。
- 本地缓存缺失时，使用节点保存的远端图片 URL 重新拉取并回补本地缓存。
- 生图接口返回 base64 图片数据时，上传到腾讯云 COS，并在画布节点、助手图片和素材数据里保存稳定 `remoteUrl`；上游已经返回远程 URL 时只保存该 URL，不再二次转存 COS。
- 登录用户跨浏览器加载同一画布时，即使本地没有 IndexedDB 图片，也能通过服务端同步的节点数据恢复图片。

## 实施范围

- 后端新增 COS 配置读取和媒体上传接口。
- 前端图片存储服务新增远端上传与远端回补能力。
- 画布图片节点、助手图片、素材图片类型补充 `remoteUrl`。
- 画布云端保存继续使用 `/api/v1/user-data/canvas` 的 `{ projects }`，并明确保存节点、连线、助手会话和项目提示词。
- 登录后进入画布库或详情页时等待云端画布数据加载完成，再显示项目列表或判断项目不存在。
- `user_data.payload` 在 MySQL 下使用 `LONGTEXT`，避免长画布 JSON 写入失败。
- 更新待测试文档，不改无关 UI。

## 验证

- 静态检查重点：上传接口路由、前端类型、`storageKey` 和 `remoteUrl` 保存路径。
- 静态检查重点：画布 store 的 `projects` 是否包含 `nodes` 和 `chatSessions`，登录同步是否整包保存到 `user_data.payload`。
- 部署后验证首页、画布页、生图页可访问；如条件允许再用接口验证媒体上传鉴权。
